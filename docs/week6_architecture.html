Architecture Decisions
PII Detection Strategy
✓ Regex in TypeScript (pii.ts)
✗ Presidio (ML, Python sidecar)
✗ AWS Comprehend (external API)
Regex runs in-process, zero external hops, zero infra. ML-based detection has better recall but requires a Docker sidecar (Presidio) or sends user text to a third party to detect PII (Comprehend — circular trust problem). Presidio sidecar is the documented production upgrade path.
Logging Database
✓ Turso (serverless SQLite, HTTP-native)
✗ Cloud SQL (persistent TCP, ~$10/mo minimum)
✗ Firestore (already provisioned, NoSQL)
Vercel serverless functions cannot hold persistent TCP connections — Cloud SQL's connection model breaks in this deployment. Turso speaks HTTP, costs zero at bootcamp scale, provides standard SQL for dashboard aggregations. Firestore (already in GCP) was the alternative, but NoSQL is awkward for SUM/AVG analytics.
Admin Route Protection
✓ HTTP Basic Auth (middleware.ts)
✗ Open (no protection)
✗ Secret query param (appears in logs)
Basic auth over HTTPS is adequate for a single admin user. Query params appear in Vercel access logs and browser history — worse than no auth because it creates a false sense of security. HMAC was considered but requires the client to sign requests, which exposes the key in browser context. HMAC is the right pattern for machine-to-machine (Week 7).
Rate Limit Backing Store
✓ Turso (persistent across invocations)
✗ In-memory (resets on cold start)
In-memory rate limiting resets on every Vercel cold start, providing almost no protection in serverless. Each function invocation starts fresh. Turso-backed rate limiting is accurate across all invocations. Atomic upsert (INSERT...ON CONFLICT DO UPDATE) prevents race conditions when concurrent requests hit the same window.
